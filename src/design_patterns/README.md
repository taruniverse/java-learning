# Design Patterns Notes

Design patterns are common ways to solve recurring design problems in object-oriented code.
They are not rules you must always use. Think of them as vocabulary: once you know the idea,
you can recognize when the pattern makes code simpler.

## Creational Patterns

These patterns help create objects in a flexible way.

- Singleton: one shared instance.
- Factory Method: let subclasses or methods choose which object to create.
- Abstract Factory: create families of related objects.
- Builder: create complex objects step by step.
- Prototype: copy an existing object instead of building from scratch.

## Structural Patterns

These patterns help connect classes and objects.

- Adapter: make one interface work like another.
- Bridge: separate abstraction from implementation.
- Composite: treat single objects and groups the same way.
- Decorator: add behavior without changing the original class.
- Facade: provide a simple front door to a complex system.
- Flyweight: share reusable objects to save memory.
- Proxy: control access to another object.

## Behavioral Patterns

These patterns help objects communicate and divide responsibilities.

- Chain of Responsibility: pass a request through handlers.
- Command: turn an action into an object.
- Interpreter: evaluate a simple language or rule.
- Iterator: access items one by one.
- Mediator: centralize communication between objects.
- Memento: save and restore state.
- Observer: notify many objects when something changes.
- State: change behavior when internal state changes.
- Strategy: swap algorithms at runtime.
- Template Method: define steps once and let subclasses customize some steps.
- Visitor: add operations to objects without changing their classes.

## How To Use These Examples

Open any pattern folder and run its `Main.java`.
Each folder also has a short `README.md` with beginner notes.
